## 📁 산출 파일 구조

```
Mulco/
├── index.html              ← 앱 진입점 (SPA 방식 단일 HTML)
├── css/
│   └── style.css           ← 전체 디자인 시스템 및 컴포넌트 스타일
├── js/
│   ├── app.js              ← 라우팅 / 화면 전환 로직
│   ├── data.js             ← 목 데이터 (Mock Data)
│   └── components/
│       ├── login.js        ← 1단계: 로그인 / 가입 화면
│       ├── setup.js        ← 2단계: 동네 & 닉네임 설정 화면
│       ├── chat.js         ← 3단계: 메인 단톡방 (탭 3개)
│       └── profile.js      ← 4단계: 유저 프로필 & 1:1 채팅 화면
└── assets/
    └── (일러스트 / 아이콘 등)
```

### 🎨 STEP 1 — 디자인 시스템 수립 (`css/style.css`)
**목표**: PRD의 컬러 팔레트를 CSS 변수로 정의하고 전역 기본 스타일을 설정한다.

| 항목 | 상세 내용 |
|------|-----------|
| CSS 변수 정의 | `--bg: #F9F9F7`, `--main: #D1E6E8`, `--sub: #E2EFE7`, `--point: #3A6073`, `--text: #2C2C2C`, `--muted: #E0E0DB` |
| 폰트 적용 | Google Fonts `Noto Sans KR` (한국어 지원, 미니멀 감성) + `Pretendard` 백업 |
| 기본 레이아웃 | 모바일 우선(max-width 430px) 세로형 레이아웃, 중앙 정렬 |
| 컴포넌트 스타일 | 버튼, 인풋, 탭, 카드, 배지, 모달, 채팅 버블 등 공통 UI 정의 |
| 애니메이션 | 화면 전환 fade/slide, 버튼 hover/active 마이크로 인터랙션 |

---

### 🏗️ STEP 2 — SPA 기반 뼈대 구축 (`index.html` + `js/app.js`)
**목표**: 단일 HTML로 4개 화면을 라우팅하는 SPA 구조를 완성한다.

| 항목 | 상세 내용 |
|------|-----------|
| HTML 뼈대 | `<div id="app">` 루트 컨테이너, 각 화면 `section` 포함 |
| 라우터 구현 | `showPage(pageName)` 함수로 `data-page` 어트리뷰트 기반 화면 전환 |
| 상태 관리 | JS 전역 객체 `AppState` (currentUser, currentRoom, currentTab) |
| 목 데이터 | `data.js`에 유저·채팅방·분양 카드·후기 샘플 데이터 정의 |

---

### 📱 STEP 3 — 화면 1: 로그인 / 가입 페이지 (`js/components/login.js`)
**목표**: 감성적인 첫 인상과 전화번호 기반 인증 UI를 구현한다.

| 항목 | 상세 내용 |
|------|-----------|
| 상단 영역 | 물결 모티프 일러스트 or SVG, 앱 로고(물꼬), 한 줄 소개 |
| 폼 구성 | 전화번호 입력 → [인증번호 받기] 버튼 → 인증번호 6자리 입력란 |
| 인증 흐름 | 목업: 전화번호 입력 후 버튼 클릭 시 인증번호 입력 폼으로 전환, 인증번호 입력 완료 시 STEP 4(동네 설정) 이동 |
| 디자인 | `--bg` 배경, 중앙 카드 레이아웃, `--point` 색상 버튼, 하단 안내 텍스트 |

---

### 🗺️ STEP 4 — 화면 2: 동네 & 닉네임 설정 페이지 (`js/components/setup.js`)
**목표**: 가입 직후 나타나는 동네·닉네임 설정 팝업형 화면을 구현한다.

| 항목 | 상세 내용 |
|------|-----------|
| 동네 선택 | GPS 위치 권한 요청 버튼 + 목록 (목업: 강남구 역삼동, 강남구 논현동 등 샘플 3개) |
| 닉네임 입력 | 텍스트 입력창, 실시간 글자 수 카운터(최대 10자) |
| 완료 처리 | [시작하기] 버튼 클릭 시 `AppState` 저장 후 메인 단톡방으로 이동 |
| 디자인 | 슬라이드업 팝업 형태, 반투명 오버레이 배경 |

---

### 💬 STEP 5 — 화면 3: 메인 동네 단톡방 (`js/components/chat.js`)
**목표**: 3개 탭을 가진 핵심 화면을 완성한다. 가장 복잡도가 높은 화면.

#### 5-1. 공통 헤더
| 항목 | 상세 내용 |
|------|-----------|
| 헤더 구성 | 동네 이름 + 참여 인원수, 오른쪽 메뉴 아이콘 |
| 탭 바 | `[전체 채팅]` / `[생물 분양]` / `[용품·수초]` 언더라인 탭 UI |

#### 5-2. [전체 채팅] 탭
| 항목 | 상세 내용 |
|------|-----------|
| 채팅 목록 | 목업 메시지 5~7개 (말풍선 스타일, 내 메시지 우측·상대 메시지 좌측) |
| 입력 영역 | 하단 고정 텍스트 인풋 + 전송 버튼 |
| 스크롤 | 메시지 목록 스크롤, 새 메시지 전송 시 자동 하단 이동 |

#### 5-3. [생물 분양] 탭
| 항목 | 상세 내용 |
|------|-----------|
| 카드 목록 | 2열 그리드, 각 카드: 사진·어종명·책임비·[보내요/받아요] 태그·닉네임 |
| 플로팅 버튼 | 우하단 `+` 버튼 → 분양 등록 모달 (어종, 책임비, 형태, 사진 업로드) |
| 카드 터치 | 카드 클릭 시 프로필 페이지로 이동 |

#### 5-4. [용품·수초] 탭
| 항목 | 상세 내용 |
|------|-----------|
| 카드 목록 | 생물 분양과 동일한 카드 레이아웃, 카테고리만 다름 |
| 목업 데이터 | 여과기·수초 트리밍 등 3~4개 샘플 카드 |

---

### 👤 STEP 6 — 화면 4: 유저 프로필 & 1:1 채팅 (`js/components/profile.js`)
**목표**: 신뢰 프로필과 1:1 채팅 진입 화면을 완성한다.

| 항목 | 상세 내용 |
|------|-----------|
| 상단 프로필 영역 | 아바타(이니셜 기반 원형), 닉네임, 동네, 한 줄 소개 |
| 후기 배지 영역 | 선택형 후기 키워드 배지 (예: `#포장이꼼꼼해요 12`, `#생물이건강해요 8`), 상위 5개만 노출 |
| 분양 이력 | 해당 유저가 올린 분양 카드 미리보기 2~3개 |
| CTA 버튼 | 중앙 큼직한 `💬 1:1 개인 채팅하기` 버튼 (`--point` 컬러) |
| 1:1 채팅 화면 | 버튼 클릭 시 해당 유저와의 1:1 채팅 뷰로 전환 (동일 채팅 UI 재사용) |

---

### 🔧 STEP 7 — 후기 팝업 구현 (공통 컴포넌트)
**목표**: 거래 완료 후 보기 선택형 후기 팝업을 구현한다.

| 항목 | 상세 내용 |
|------|-----------|
| 트리거 | 분양 카드 상태를 [거래완료]로 변경 시 팝업 자동 노출 |
| 키워드 목록 | `#생물이건강해요`, `#포장이꼼꼼해요`, `#물생활꿀팁을공유해줘요`, `#시간약속을잘지켜요`, `#친절해요` (5개) |
| 선택 UI | 멀티 선택 가능한 칩(Chip) 형태, 선택 시 `--point` 색상으로 강조 |
| 제출 처리 | 선택한 키워드를 상대방 프로필 배지에 카운트 누적 |
